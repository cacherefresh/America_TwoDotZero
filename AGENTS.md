## Implementation notes

Status: implemented on `feature/futuristic`, merged into `sanctuary`'s line on `feature/merge-futuristic`. Web-only (the holographic layer is `kIsWeb`-gated; other platforms fall back to a plain landing host). Note the app is web-only in practice regardless: `game`, `poe`, `abe` and `about` all import `dart:html`/`dart:ui_web` unconditionally, so non-web targets don't compile.

- **Three.js background**: vendored (not CDN) at `flutter_app_wrapper/web/three/three.module.min.js` (r170) + a hand-written bridge `flutter_app_wrapper/web/three/holo-background.js` (particle field + rotating wireframe shapes, reacts to pointer/scroll/focus). Bridged into Dart via `dart:js_interop`/`package:web` in `flutter_app_wrapper/lib/holographic/interop/`.
- **Floating windows**: `flutter_app_wrapper/lib/holographic/holographic_window.dart` — three modes (`HoloWindowMode`): a glowing drifting `orb`, a glass-morphic `window` opened by tapping the orb, and an edge-to-edge `fullscreen` view reached from the top nav bar. All three render the *same* tree shape, varying only decoration and `Visibility` flags, because moving `slot.child` in the tree would tear down and reload the iframes.
- **Landing page**: `flutter_app_wrapper/lib/holographic/holographic_landing_page.dart` — orbs are auto-arranged on an ellipse around the viewport center so they're all visible without scrolling. It is also the single host that mounts every app's page.
- **Under-construction banner**: `under_construction_banner.dart` + `under_construction_copy.dart`. The pre-holographic landing page's under-construction notice and 52%-of-donations pledge were left only on the non-web fallback by `feature/futuristic`, which meant the deployed site lost them entirely. They now sit in a glass strip along the bottom of the landing page — collapsed it shows the pledge and the donation handles, tapping it opens the full text. Both the banner and the non-web fallback read one shared constant, and `test/under_construction_copy_test.dart` pins that constant character-for-character.
- **Single source of truth for the top menu + orbs**: `flutter_app_wrapper/lib/config/app_registry.dart` (`AppEntry` + `buildAppRegistry()`). Both `home_page.dart`'s AppBar and the landing page's orbs are built from this one list — adding an app means adding one `AppEntry` here, nothing else. `about` is registered here too.
- **Fixed (was a known tradeoff on `feature/futuristic`)**: each app's `pageBuilder()` used to be called twice — once for its top-menu tab's `IndexedStack` entry, once for its landing orb — so `GameView`/`POEView`/`ABEView`/`AboutView` each mounted two live iframes loading the same remote site twice. There is now a single call site: `home_page.dart` builds `_appPages` once and hands it to the landing host, which owns the only mounted copy. Selecting an app in the nav bar promotes that app's *existing* window to `fullscreen` instead of building a second one, so the orb still expands independently and the "click orb → see it in the holographic window" behaviour is unchanged.
- Fixed in passing: `SYSOPS_README.md`'s `--web-renderer html` build flag (removed upstream in the installed Flutter version) and a missing `assets/config.yaml` asset declaration in `pubspec.yaml` that made `AppConfig` unusable.
- **Still open**: `SYSOPS_README.md` documents a `--wasm` build option, but the `dart:html` imports above make the wasm dry run fail, so release builds are CanvasKit/JS only for now.

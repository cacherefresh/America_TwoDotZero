## Implementation notes

Status: implemented on `feature/futuristic`, web-only (holographic layer is `kIsWeb`-gated; other platforms fall back to the old plain landing text).

- **Three.js background**: vendored (not CDN) at `flutter_app_wrapper/web/three/three.module.min.js` (r170) + a hand-written bridge `flutter_app_wrapper/web/three/holo-background.js` (particle field + rotating wireframe shapes, reacts to pointer/scroll/focus). Bridged into Dart via `dart:js_interop`/`package:web` in `flutter_app_wrapper/lib/holographic/interop/`.
- **Floating windows**: `flutter_app_wrapper/lib/holographic/holographic_window.dart` — glowing drifting orb ↔ glass-morphic expanded window. Each app's real content widget is always mounted (`Visibility(maintainState: true)`), never rebuilt on open/close, so the Game/POE/ABE iframes don't reload each time a window opens.
- **Landing page**: `flutter_app_wrapper/lib/holographic/holographic_landing_page.dart` — orbs are auto-arranged on an ellipse around the viewport center so they're all visible without scrolling.
- **Single source of truth for the top menu + orbs**: `flutter_app_wrapper/lib/config/app_registry.dart` (`AppEntry` + `buildAppRegistry()`). Both `home_page.dart`'s AppBar/`IndexedStack` and the landing page's orbs are built from this one list — adding an app means adding one `AppEntry` here, nothing else.
- **Known tradeoff**: each app's `pageBuilder()` is called twice (once for its top-menu tab, once for its landing orb), so e.g. `GameView` mounts two independent iframes simultaneously. Not fixed — de-duplicating would mean the orb can't show an independent expand/collapse view separate from the tab, which conflicts with the "click orb → see it in the holographic window" ask above.
- Fixed in passing: `SYSOPS_README.md`'s `--web-renderer html` build flag (removed upstream in the installed Flutter version) and a missing `assets/config.yaml` asset declaration in `pubspec.yaml` that made `AppConfig` unusable.
